## GUIDELINES FOR DATABASE DESIGN

The database must support the system requirements. Every major system function that requires data storage should have corresponding database structures.

**Use meaningful table names**. Table names should clearly describe the data being stored.

**Use meaningful field names**. Field names should be descriptive, consistent, and easy to understand.

**Do not include unused tables or fields**. Every table and field presented in the documentation should have a purpose within the system.

Ensure consistency across the manuscript. The database design should be consistent with the system architecture, use case diagrams, data flow diagrams, system design, and implemented system.

If a table does not fit properly on one page or is cut off, move the entire table to the next page. Do not split the table in a way that makes the information difficult to read.
